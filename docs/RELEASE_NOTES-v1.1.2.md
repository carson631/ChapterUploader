# ChapterUploader v1.1.2 发布说明

> 承接 v1.1.1（修好「读不到章节目录」与日期/时间填不上）。这一版解决的是
> **「日期时间设好了，但程序没去点『定时发布』按钮」** 的疑惑，并给提交这一环加了两道保险。

## 1. 为什么「设好时间却不点按钮」——演练模式是默认勾上的

「演练：只核对时间，不点『定时发布』」**默认是勾选状态**（安全优先）。勾着它时程序故意不点提交，
一章都不会真正排期。之前的文案叫「演练：只填表不提交」，日志里也只是淡淡一句
「【演练】日期时间已核对，关闭弹窗，不提交」，很容易被理解成「程序漏了点按钮」。

这一版的改动：

| 位置 | 现在长什么样 |
|---|---|
| 复选框 | 「演练：只核对时间，不点『定时发布』」，悬停有完整解释 |
| 开始按钮 | 勾着演练时显示 **「开始定时发布（演练·不会真发）」** |
| 排期提示 | 追加「· 演练中：只核对时间，不会点『定时发布』」 |
| 日志首行 | `【演练模式：只填表核对时间，不会点「定时发布」】` 或 `【真实发布：会点「定时发布」并提交】` |
| 每章 | `【演练】日期时间已核对；演练模式按设计不会点「定时发布」，关掉弹窗继续下一章` |
| 跑完 | 弹窗提示「刚才只是演练，没有点『定时发布』，一章都没有真正排期」 |

**要真发**：取消勾选演练 → 按钮变成「开始定时发布」→ 再点一次。

## 2. 提交按钮：加了「开关态护栏」和「点不动就重点一次」

- **护栏**：定时发布开关没打开时，弹窗底部那个按钮写的是「确认发布」，点下去是**立即上架**。
  原来的实现会把「确认发布」也算作命中；现在只要开关没开就拒绝点击，并在日志里说明原因。
- **找按钮更宽容**：文本匹配「定时发布」失败时，退回弹窗底部最后一个 `.ant-btn-primary`。
- **点了没反应会重试**：提交后 12 秒内弹窗既没关、也没有任何提示，程序会先试着点一次二次确认框，
  再用原生 `element.click()` 重点一次；仍然没反应才报错（并且不再静默跳章）。
- 日志会写清点击结果：`已点「定时发布」（开关开，点击后：closed / loading / none），等结果…`

## 3. 窗口在后台时不再"卡 20 秒"

实测客户端窗口被遮挡/最小化时：`document.hidden === true`，Chromium 把定时器节流到 1 秒一跳，
而且日期/时间面板根本不会渲染出来 —— 原来的「轮询等面板」在后台每章要白等 20 多秒。

现在检测到页面隐藏就跳过面板路径，直接走键入兜底。实测同样的填写从 **>20 秒降到约 3 秒**，
且提交出去的 `publishtime` 依然正确（用拦截 XHR 抓包核对过：`publishtime=2026-11-06 19:00`、`status=5`）。

## 4. 日志落盘

`exe目录/logs/run-YYYYMMDD.log`，每行带时间戳，每次启动插一条分隔线（含版本号）。
出问题不用截屏，把当天这个文件发过来即可。

## 真机验证记录

用 DevTools 协议连真实客户端（5.24.0）逐项核对：

| 场景 | 结果 |
|---|---|
| 开关关着时调用提交 | 拒绝，且**没有**发出任何 `publishChapter` 请求（不会误上架） |
| 开关开着、`2026-11-06 19:00` | 命中「定时发布」→ 请求 `publishtime=2026-11-06+19:00`、`status=5` |
| 页面隐藏（窗口在后台） | 3.2 秒填完，`via = typing / typing`，提交参数同样正确 |
| 跨月/跨年日期（2026-12-01、2027-01-02） | 日历翻页正常，值正确 |

> 验证时用脚本钩住 `XMLHttpRequest.send`，只拦 `publishChapter` 并让它报错，所以**没有真的发布任何章节**。
